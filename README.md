# 千紗的一週 — 遊戲開發交接文件

> 最後更新：2026-10-25  
> 用途：方便下一輪對話快速接手開發、除錯與擴充  
> 遊戲形態：單檔 HTML + 內嵌 CSS/JS 文字冒險（無需外部依賴）

---

## 1. 專案概要

- **作品名稱**：千紗的一週（可自訂女主角／男朋友名稱）
- **類型**：NTR／露出／公共調教向文字遊戲
- **技術**：單一 `.html` 檔，純前端（localStorage 存檔）
- **核心循環**：早晨選配件 → 日間地點事件 → 回家 → 晚間夜遊（可選）→ 隔天

---

## 2. 角色與關係設定

| 角色 | 預設名 | 說明 |
|------|--------|------|
| 女主角 | 千紗 | 玩家控制，可自訂名稱 |
| 男朋友 | 山本 | 可自訂名稱；依「知情度／屈服度」改變態度與行為 |

### 男朋友行為分層（知情度 know）

| 區間 | 行為 |
|------|------|
| ≤30 | 幾乎無 NTR 互動；≥20 時會有心中 OS |
| 30 < know ≤60 | 會懷疑、可能跟蹤（顯示機率）；被跟蹤發現 +知情度（上限相關） |
| 60 < know ≤90 | 對話明示發現出軌／被使用，憤怒與不解 |
| >90 | 更接近接受／參與；屈服度高時會主動安排 |

### 屈服度（yield, 0–200）

- **<100**：不會出現「山本主動安排夜間使用」
- **≥100**：可能出現主動安排
- 約會（需知名度≥50 且屈服度≥50）可降低知情度與屈服度

### 其他累積計數

- 口 / 穴 / 後穴 / 經驗人數 / 騷擾人數 / **露出經驗**

## 3. 數值一覽

| 數值 | 範圍 | 說明 |
|------|------|------|
| 體力 energy | 0–100 | 白天用；耗盡可回家 |
| 夜遊體力 nightEnergy | 上限 30 | 晚間專用，與白天體力分開 |
| 沉淪度 corruption | 0–100 | 影響接受選項、敘事語氣 |
| 興奮度 arousal | 0–100 | ≥50 觸發高潮事件，結束後歸 0 |
| 知名度 fame | 0–100 | 決定事件類型與機率 |
| 知情度 know | 0–100 | 男朋友知情程度；一般事件增幅有上限 |
| 屈服度 yield | 0–200 | 目擊後上升；影響男朋友態度 |
| 露出經驗 exposure | 0–100+ | 解鎖野外露出、影響露出敘事 |

### 每日重置（早晨）

- 興奮度 → 0  
- 體力 → 70  
- 配件全部清空，重新選擇  
- 衣著狀態重置（依是否勾選「不穿內衣／內褲」決定 bra/panty）

### 開始前可自訂初始值

- 女主角名稱、男朋友名稱  
- 知名度、知情度、**屈服度**、**露出經驗**

---

## 4. 配件（早晨選擇）

可複選：

- 跳蛋、肛塞、假陽具、胸鍊  
- 不穿內衣、不穿內褲  

影響：

- 事件機率（每多一件約 +5%，有上限）  
- 事件中的嘲弄與玩弄台詞（`getToyMock` / `getToyPlay`）  
- 露出時：若已選「不穿內衣／內褲」，脫衣階段預設已脫

---

## 5. 地點系統

### 校內（CAMPUS_LOCS）

- 自己的教室、美術教室、屋頂、女廁、空教室、體育館器材室、老師辦公室  

### 校外（OUT_LOCS）

- 便利商店巷弄、河岸、舊公寓、停車場  

### 移動

- 校外：地鐵 or 他人的車（需沉淪≥50 且知名度≥50）  
- 地鐵途中可觸發騷擾／被操（拍攝機率更高）  
- **列車事件結束後必須抵達目的地**（`arrive_dest`），再觸發該地點事件  

### 事件地點人數（LOC_PEOPLE）

依地點亂數，例如：

- 教室 6–20、便利商店 1–5、空教室 1–2、河岸 5–10、電車 8–25  

用途：

- 影響知名度上升：`fameGain ≈ base × (1 + 人數/5)`  
- 露出經驗增加量  
- 露出時的「發現人數」上限  

### 事件後流程（重要）

事件（騷擾／偷拍／被操／露出結束）結束後：

→ **留在原地**（`stay_loc`），選項為：

1. 進行日常活動  
2. 什麼都不做，休息  
3. 野外露出（條件符合時）  
4. 離開此地，前往其他地方（才進 `after_loc`）  
5. 直接回家  

**不要**一結束事件就強制跳回地點選擇。

## 6. 知名度與事件機率（概要）

| 知名度 | 主要事件 |
|--------|----------|
| <10 | 偷窺／偷拍為主 |
| 10–30 | 騷擾為主 |
| 30–50 | 單人被操 + 騷擾 |
| 50–80 | 單人／多人被操機率共享 |
| ≥80 | 多人比重提高；有機率觸發「亂交日」 |

配件會提高對應機率。  
拍攝／上傳機率：一般約 70%，電車約 90%。

---

## 7. 多段事件（騷擾／被操）

選項：

- **反抗**：扣較多體力；成功機率 騷擾 50%／被操 30%；成功則中斷  
- **忍受**：扣較少體力，沉淪與興奮上升，事件繼續  
- **欣然接受**：需沉淪或興奮 ≥50；不扣體力，數值上升更多，事件繼續  

事件會依 `shotsLeft` 與強度推進，直到對方「滿意」（射精次數概念）。  
結束時有嘲弄、射在哪裡等收尾；沉淪 >50 時事後描寫偏「回味／餘韻」。

### 騷擾連續行為鏈（已實作）
- 使用 `HARASS_CHAIN`：每個動作有 text 與 next 可銜接列表
- 例：嘴邊摩擦（mouth_rub）→ 下一階段傾向強迫口交（mouth_force）
- 例：摩擦陰蒂（finger_clit）→ 下一階段傾向手指插入前穴
- 每階段依上一 actionKey 的 next 隨機選取，保持行為連貫性

## 8. 露出系統（重點）

### 解鎖

| 露出經驗 | 可選時機 |
|----------|----------|
| ≥20 | 夜遊可選「野外露出」 |
| ≥50 | 白天校外可選 |
| ≥70 | 白天校內也可選 |

### 即時衣著狀態（S.clothes）
- 欄位：top / bottom / bra / panty（true=穿著）
- 早晨依配件「不穿內衣／內褲」初始化
- 露出脫衣會同步寫入 S.clothes，狀態持續到玩家主動「穿回」
- stay_loc 會根據目前脫下的衣物顯示「穿回上衣／下衣／內衣／內褲」選項
- 結束露出不再強制穿回

### 流程

1. 脫衣（上衣／下衣／內衣／內褲，可多次；文本依是否穿內衣／內褲分支）  
2. 露出行為：待在原地（被發現值+1）／遊蕩（+1.5）／自慰（+2）／結束露出（維持衣著）  
3. 每次行動：
   - 累加 **被發現值** → 被抓正著機率 ≈ 被發現值 × 20%  
   - 有機率增加 **發現人數**（不超過當地人數）  
4. 被抓正著 → 圍觀／羞辱描述 → 轉入騷擾或被操  

### 發現人數（found）

- 代表「已經發現你在露出的人數」  
- 上限 = 事件地點人數  
- 影響文本，例如：  
  「身邊有 2 名【同學】發現了你，他們正目不轉睛地看著你……乳尖……」  
- 依露出經驗分層：低→羞恥不適；中→羞恥+微興奮；高→偏興奮  

### 露出敘事要求

- 細膩寫心態、刺激感、肌膚碰空氣的反應  
- 可依發現人數與露出經驗切換語氣

## 9. 其他系統摘要

- **高潮**：興奮度 ≥50 觸發；詳細生理描寫；沉淪↑、體力↓、興奮歸 0；結束後回到觸發前脈絡  
- **亂交日**：高知名度有機率；選項鎖定「繼續當肉便器」直到體力歸零  
- **男友目擊**：依知情度機率；專用視窗寫當下想法與後續動作；提高知情度與屈服度  
- **日常活動**：校外需具體（買保險套、逗貓、河岸散步等），非空泛「日常活動」  
- **體位合理性**（創作文案時遵守）：三穴需三明治等合理姿勢；單穴不限  
- **多人動態體位系統**（已實作）：
  - 每位參與者每階段獨立 50% 機率決定是否插入（至少保留 1 人）
  - 身體部位池：口、胸、穴、後穴、左手、右手（等機率、不重複分配）
  - 依當前部位組合過濾合理體位：躺下／趴下／站立／跪姿／坐著上位
  - 規則摘要：有「口」排除站立；口+穴+後穴同時排除坐著上位；雙穴+多人排除站立
  - 文本依人數（2/3/4）、部位組合、體位、強度、沉淪度動態產生

## 10. 敘事與文風要求（延續自長篇創作期）

- 偏日式色情小說語氣，少不必要逗號，但保留正常標點與分句  
- 不要過度 AI 腔、不要一直換行  
- 重口可接受：露出、公共、調教、道具、NTR、拍攝上傳  
- 人物語氣可輕蔑、口語化  
- 二穴／三穴／胸部使用需合理完整描述（抽插節奏、敏感點等）  
- 事後可依沉淪度給「回味」變體

## 11. 技術結構速查

| 項目 | 說明 |
|------|------|
| 狀態物件 | `S`（含 stats、toys、flags） |
| 段落表 | `P`（passage → 渲染函式） |
| 跳轉 | `go(name, extra)` |
| 數值變更 | `fx(changes, explain[], aftermath)` |
| 存檔 key | `chisa-week-v19`（版本可遞增） |
| 露出狀態 | `S.flags.expo`：`discover`（被發現值）、`found`（發現人數）、`people`（當地人數）等 |
| 當前地點 | `S.flags.currentLoc` / `currentLocName` → 事件後 `stay_loc` |
| 多人體位 | `decideInsertCount` → `assignParts` → `getPossiblePositions` → `generateMultiStageText`；結果暫存於 `evt.currentParts` / `evt.currentPos` |

主要流程函式：

- `resolveLocation` → 決定是否觸發事件或直接 `stayAtLocation`  
- `startHarass` / `startSex` / `finishEvt`  
- `startExposure` → `expo_do` → `expo_caught` / `expo_end`  
- `stayAtLocation`：事件後原地選單

## 12. 已知應維持的行為（除錯檢查清單）

1. 事件結束後 → **stay_loc**，不是直接 after_loc  
2. 地鐵事件結束 → **arrive_dest**，再觸發目的地事件  
3. 校外事件後的「離開此地」才依 lastArea 給校外優先選項  
4. 每天早晨：興奮度 0、體力 70、配件與衣著狀態重置  
5. 發現人數 ≤ 當地人數  
6. 露出解鎖門檻依經驗與時段／區域  
7. 設置頁可調：知名度、知情度、屈服度、露出經驗
